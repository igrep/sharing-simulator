# Sharing Simulator

Simulate what happens if you share an object between threads in JavaScript.

Visualize the object reference graph using mermaid.

## Components

consists of two HTML apps:

### index.html

Feed query parameters to the embedded.html through the following form controls (The table below represents the layout of the form controls):

```
+------------------------------+--------------------------------+
| [SE: Select Evaluation Mode]                                  |
+------------------------------+--------------------------------+
| IM: Input Main Thread Code   | IW: Input Worker Thread Code   |
|                              |                                |
|                              |                                |
|                              |                                |
|                              |                                |
+------------------------------+--------------------------------+
```

- SE: Dropdown menu to select evaluation mode from the following options:
    - Simulate Transferring `ArrayBuffer`
    - Simulate Sharing `ArrayBuffer` (Not transferring ownership)
    - Run real worker code (Not simulating)
- IM: `<textarea>` for inputting main thread code.
- IW: `<textarea>` for inputting worker thread code.

Every time the user changes the input, the embedded.html is `pushState`ed with the new query parameters (with 200ms throttling).

### embedded.html

Evaluates the main thread code and worker thread code specified in the query parameters, collect unused references, and visualizes the object reference graph using mermaid. It consists of the two panes:

```
+---------------+--------------+
|  Graph Pane   | Errors Pane  |
|               |              |
|               |              |
+---------------+--------------+
```

- Graph Pane: Displays the object reference graph using mermaid.
- Errors Pane: Displays any errors that occur during the evaluation of the code.

(UNAVAILABLE in the "real" mode) In either pane (TBD), user can see invalid references, where either thread tries to access an object that is not available (i.e., the counterpart thread's `Tracker.hasMarkUnused` returns `true`) in its context.
